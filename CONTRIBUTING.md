# Contributing

Thanks for your interest in contributing. A few simple rules to help us keep the
repo healthy and welcoming.

1. Fork the repo and create a feature branch: `feature/short-description` or `fix/short-description`.
2. Keep changes focused and create small PRs.
3. Run tests locally before opening a PR:

```bash
npm install
npm run test
```

4. Commit messages: use conventional style `feat:`, `fix:`, `chore:`, `docs:`.
5. Add or update tests for any logic you change.
6. Link the issue in your PR and include a short description of the change.

PR checklist
- [ ] Branch named correctly
- [ ] Tests added/updated
- [ ] Linting passes (`npm run lint`)
- [ ] Changes documented if applicable
